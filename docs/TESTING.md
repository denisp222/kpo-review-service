# Лабораторная №7: инфраструктура тестирования

Проверяется готовый прототип задач №10, 11, 13, 14, 15, 16, 18 и серверный модуль рецензирования. Полное приложение ещё не реализовано. Переключение ролей, локальное хранение и сведения о файле остаются ограничениями прототипа.

## Среда и запуск

Node.js 24, PostgreSQL 16 для интеграционных тестов, Chromium для пользовательских сценариев. Версии зависимостей зафиксированы в package-lock.json.

```text
npm ci
npm run db:generate
npx playwright install chromium
```

Создайте отдельную базу review_test. Укажите DATABASE_URL и TEST_DATABASE_URL для этой тестовой базы, затем выполните `npm run db:migrate`. Интеграционные тесты очищают учебные таблицы: рабочая база с пользовательскими данными для них не подходит.

```text
npm run quality
```

Команда удаляет предыдущие отчёты, проверяет оформление, ESLint, типы, 68 тестов Vitest с покрытием, собирает сервер и прототип, выполняет 25 тестов Chromium. При ошибке код завершения ненулевой. Сборка и браузерные тесты выполняются только после успешных предыдущих шагов. GitHub Actions запускает весь набор для push и pull request; проверка quality обязательна для main.

Отдельные команды:

- `npm run test:unit` — 56 модульных тестов без базы и браузера.
- `npm run test:e2e` — сборка HTML и 25 тестов браузера без базы.
- `npm run test:coverage` — модульные и интеграционные тесты с покрытием.
- `npm run test:report` — открыть подробный HTML-отчёт Playwright через локальный сервер.
- `npm run snapshot -- --stage infrastructure` — повторить полный набор и сохранить датированный снимок метрик с SHA коммита.

## Уровни тестирования

| Уровень                     | Инструменты                           | Проверяемое поведение                                                                                     |
| --------------------------- | ------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| Модульный: 56 тестов        | Vitest                                | 25 правил рецензирования, 9 проверок демонстрационной авторизации, 22 проверки хранилища прототипа        |
| Интеграционный: 12 тестов   | Vitest, Supertest, Prisma, PostgreSQL | HTTP-ответы, права доступа, сохранение результата и уведомления, откат при ошибке и конкурирующие решения |
| Пользовательский: 25 тестов | Playwright Test, Chromium             | Семь задач прототипа, основной и ошибочные сценарии, сохранение после обновления, мобильный экран и сброс |

Каждый браузерный тест получает отдельный контекст. HTML открывается через file://, сеть отключена. Тесты не зависят от порядка запуска и не используют произвольные паузы: Playwright ожидает состояние элементов. Для сохранения рецензии проверяется сообщение об успехе, затем выполняется возврат к очереди. Повторные попытки отключены, чтобы не скрывать нестабильность.

## Связь задач и тестов

| №   | Задача                   | Реализованные проверки                                                                                                       |
| --- | ------------------------ | ---------------------------------------------------------------------------------------------------------------------------- |
| 10  | Список и условие задания | Три исходных задания, условие и критерии, узкий экран                                                                        |
| 11  | Фильтр статусов          | Не сдано, на проверке, проверено; пустой результат и возврат ко всему списку                                                 |
| 13  | Отправка                 | Четыре допустимых формата, отсутствие файла, EXE, пустой и слишком большой файл, сохранение и запрет повторной отправки      |
| 14  | Статусы                  | Отправка, оценка, отклонение, перезагрузка и сброс                                                                           |
| 15  | Очередь                  | Только ожидающие работы; проверенные и отклонённые исключаются                                                               |
| 16  | Рецензия                 | Корректное решение, -1/101/дробная/пустая оценка, обязательный текст, причина отклонения, отсутствие формы оценки у студента |
| 18  | Уведомления              | Пустой список, создание, переход к результату, прочтение выбранного сообщения и сохранение другого непрочитанным             |

Идентификаторы T10…T18 стоят в названиях тестов. Отчёт task-results.json строит связи по фактическим результатам, а не по вручную проставленным отметкам. Один тест может относиться к нескольким задачам.

## Автоматические отчёты

| Файл в reports           | Содержание                                                                              |
| ------------------------ | --------------------------------------------------------------------------------------- |
| summary.html             | Автономная сводка, открывается без сервера и сети: метрики, задачи и все результаты     |
| playwright/index.html    | Подробности пользовательских тестов и прикреплённые снимки успешного основного сценария |
| e2e-results              | Скриншот, контекст и trace.zip при падении теста                                        |
| junit.xml, e2e-junit.xml | JUnit для серверных и браузерных тестов                                                 |
| tests.json, e2e.json     | Полные машинные результаты                                                              |
| coverage/index.html      | Покрытие серверных файлов и prototype/src/store.ts                                      |
| metrics.json, metrics.md | Числа, время, SHA коммита и ссылка на CI                                                |
| task-results.json        | Связь результатов с семью задачами прототипа                                            |

Порог покрытия — 80% строк, ветвей, функций и выражений. React-компоненты не включены в процент покрытия; их поведение проверяется браузером. Время проверок не включает установку пакетов, браузера и подготовку базы. Время CI и локального компьютера сравнивается только с учётом разной среды.

В GitHub отчёты загружаются как артефакт даже при ошибке обязательного шага. При ранней ошибке некоторые файлы могут отсутствовать — это отсутствие результата, а не успешная проверка. Для просмотра трассировки: `npx playwright show-trace путь/trace.zip`.
